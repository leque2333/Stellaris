# TurnFlow

[English](README_EN.md) | 简体中文

**面向 AstrBot 私聊的消息防抖 + 动态撤回插件。**

连续发消息时，先等你说完，再合并交给模型；机器人还没回复完时，如果你又补充或改口，就阻止过时的回复继续发送，并在平台支持时尝试撤回已经发出的部分，结合更新后的内容重新处理。

**只处理私聊。已完整发送的回复不会因为下一条消息而自动撤回。**

## 消息防抖：连续消息合并处理

聊天时，一句话经常被拆成几条发送。TurnFlow 在收到消息后短暂等待，把等待期间的后续文字、图片合并处理，避免每收到一小句就触发一次独立回答。

例如，在收集等待内接连发送：

```text
用户：帮我写封请假邮件
用户：明天请一天假
用户：语气简短一点
```

这三条会作为同一份输入交给模型，而不是分别回答三个尚未完整的要求。文字与图片的相对顺序会被保留；支持输入状态通知的平台还可以在用户打字时继续等待。

默认基础等待为 **2 秒**。动态防抖根据内置续发规则调整等待时间，并非每条消息固定等待 2 秒；从第一条消息起，整轮收集默认最多 **30 秒**，不包含图片转述和模型生成时间。以配置的指令前缀开头的消息不参与合并。

## 动态撤回：补充时停止过时回复

防抖解决的是“回答前等一等”，动态撤回处理的是“已经开始回答，但用户又补充了”。它不只是从待处理队列里删除用户撤回的消息，也会处理机器人尚未完成的回复。

例如，机器人正在按“明天请假”写邮件，你补充“改成后天，不是明天”。只要旧回复尚未完成，插件会：

1. 阻止旧回复的后续内容继续发送，将原有输入与新的补充合并后重新处理。
2. 如果旧回复已发出一部分，尝试通过平台撤回这些已捕获的消息；未发出内容时无需撤回。
3. 尝试回滚失效回复对应的历史，防止被打断的旧结果继续影响后续回答。回滚带有保护，不应覆盖更新的对话。

### 哪些消息会受影响

| 情境 | TurnFlow 的处理 |
| --- | --- |
| 收集等待期间继续发送消息 | 继续合并，等待收集结束后再请求模型。 |
| 模型生成中或回复尚未发送完时补充消息 | 中断过时的回复，结合原有输入和补充内容重新处理。 |
| 未完成的回复已经发出部分内容 | 在平台支持且有权限时尝试撤回已捕获的部分；流式或分段输出也遵循这一规则。 |
| 在收集期间撤回自己的一条消息 | 从待处理内容中移除它；全部撤回后不再发起空请求。 |
| 上一条回复已经完整发送 | 正常处理新消息，不撤回上一条完整回复。 |

**动态撤回不是对已完成回复的事后编辑，也不是聊天记录清理器。** 平台不支持撤回或撤回失败时，已发出的部分可能仍然可见，但插件仍会阻止旧回复继续发送。关闭 `enable_humanoid_recall` 也只关闭撤回操作，不关闭回复中断。

“中断”主要指阻止过期结果继续进入对话，不保证模型服务端停止计算或停止计费；已看见的内容也无法变成未读。历史保护与第三方插件的兼容边界见下方“输出与平台边界”。

## 安装

需要可运行的 AstrBot 环境，并已配置消息平台和聊天模型。插件不声明额外 pip 依赖。

在 AstrBot 的插件管理页面使用仓库地址安装：

```text
https://github.com/Yuimi-chaya/astrbot_plugin_turnflow
```

也可以将源码放入 `data/plugins/astrbot_plugin_turnflow/`，确保该目录下直接包含 `main.py` 和 `metadata.yaml`，然后重启或重载插件。不要同时启用另一份消息防抖或回复中断插件。

### 从旧插件迁移

TurnFlow 使用新的插件标识 `astrbot_plugin_turnflow`，版本从 `1.0.0` 独立计数，不是旧插件的版本回退。

1. 备份旧插件配置，等待正在处理的对话结束。
2. 停用 `astrbot_plugin_continuous_message` 及其二开版本。
3. 安装 TurnFlow，在管理面板重新设置需要保留的配置。旧配置不会自动迁移到新标识。
4. 重启 AstrBot，避免旧实例残留的发送包装影响新实例；在新私聊中进行下文的验收。

不需要删除聊天历史、Cookie、样本文件或共享 Python 包。旧版的联网解析及本地样本学习配置在本插件中不生效。

## 配置

在 AstrBot 管理面板编辑插件配置。完整字段与默认值见 [_conf_schema.json](_conf_schema.json)。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `enable` | `true` | 启用私聊消息防抖与动态撤回处理。 |
| `debounce_time` | `2.0` 秒 | 基础收集等待时间。 |
| `enable_dynamic_debounce` | `true` | 按内置规则判断是否可能继续发送；不是模型预测或聊天样本学习。 |
| `min_debounce_time` / `max_debounce_time` | `1.2` / `8.0` 秒 | 动态等待范围。 |
| `max_collection_wait` | `30.0` 秒 | 从本轮第一条消息起计算的收集上限；不包含图片转述和模型生成时间。实际不低于基础等待时间。 |
| `enable_typing_detection` | `true` | 使用平台提供的输入状态；仍受整轮收集上限约束。 |
| `enable_recall_filter` | `true` | 处理用户撤回通知。 |
| `enable_humanoid_recall` | `true` | 尝试撤回未完成回复的已发送部分。关闭它不会关闭旧轮次中断。 |
| `enable_ordered_image_caption` | `true` | 在主模型非原生多模态且已配置图片模型时，按图片位置插入转述。 |
| `caption_timeout` | `20.0` 秒 | 单张图片转述的超时，与主聊天模型超时不同。 |
| `command_prefixes` | `["/"]` | 这些前缀开头的消息不参与合并。 |
| `invalidated_turn_retention_seconds` | `180.0` 秒 | 保留失效轮次状态以拦截迟到结果；应覆盖实际可能的迟到时间。 |

建议先保持默认值。续发仍容易被截断时再调高基础等待；感觉等待过久时，先检查输入状态与动态等待配置。

`merge_separator`、`forward_prefix`、`recall_grace_seconds`、`enable_reasoning_content_fallback` 是隐藏的旧配置兼容字段，不再影响行为。

## 输出与平台边界

- 代码包含非流式、非流式分段、流式及流式转分段处理。实际行为受 AstrBot 版本、适配器及其他发送插件影响，需在部署环境验证。
- 主模型、备用模型顺序、流式与分段策略由 AstrBot 控制。插件让流式上游异常继续向核心传播，不将其直接当作平台发送失败；它不实现独立备用模型路由。
- QQ 引用、合并转发、撤回依赖 aiocqhttp / OneBot v11 的相应能力；输入状态依赖 NapCat 等适配器是否提供通知。其他平台不保证拥有这些能力。
- 有序图片转述使用 AstrBot 配置的图片模型。默认转述提示为中文；非默认的自定义转述提示会被保留。它不会改用主聊天备用模型来替代图片模型。
- 普通链接保留为文本；QQ 卡片仅在本地提取原链接。不抓取目标网页，不扫描本地聊天记录做学习。平台消息读取和图片模型调用仍可能联网。
- 不从模型的 `reasoning_content` 中猜测或提取可见答复。
- 历史回滚带有轮次代际保护；无法识别其他插件转换后的上下文时选择保留，不保证所有第三方上下文格式都能被清理。
- 与当前事件发送调用无关联的独立机器人发送不会被捕获或自动撤回。

## 安装后验收

分别开启实际使用的流式、非流式和分段模式，测试：

1. 连发两句话，确认形成一轮回复。
2. 撤回待处理消息并马上重发，确认新消息未被旧计时器吞掉。
3. 在生成中或部分回复发出后补充内容，确认旧输出停止；支持撤回的平台检查已发送部分。
4. 在完整回复后再发送消息，确认旧回复不被撤回。
5. 在测试环境让主模型超时，检查 AstrBot 是否调用配置的备用模型，并确认没有被误判为平台发送失败。

自动测试使用 AstrBot API 替身，不等于真实平台端到端验证。首版尚未完成真实服务器上的备用模型切换及所有第三方发送插件组合验收。

报告问题时，请提供 AstrBot、适配器和插件版本、发送模式、最小复现步骤及脱敏日志。不要提交 API 密钥、账号凭据或完整私聊记录。

## 开发

在仓库根目录使用 Python 3.11 运行离线回归测试：

```console
python -B -m unittest discover -s tests -v
```

构建可安装压缩包：

```console
python -B tools/build_release.py --version 1.0.0
```

产物位于 `dist/astrbot_plugin_turnflow-1.0.0.zip`。构建会检查源码、归档路径及解压后的回归测试，并拒绝覆盖已有产物。安装包不包含测试、构建工具、缓存或本地开发笔记；完整测试与工具保留在公开仓库中。
